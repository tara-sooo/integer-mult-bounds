# First milestone result

**Status: `SOURCE_SUPPORTED_TYPED_BOUNDARY`** for one Section 4 power-width
interchange child in the original multiplication construction.

This status covers the theorem's `Swap_(k-1)` array call and its paid
interface. It does not establish that the Issue 13 `FSa` carrier is passed
to such a call. Issue 13 remains accurately described as
`MISSING_TYPED_INTERFACE` for its particular compiled producer/profile.

## Small exact check

The checker exhaustively evaluates the rank-one local shear for the reduced
instance `A=diag(1,0)`, `q=3`, `b=1`. It checks all nine `(h,d)` pairs and
both values of an arbitrary dirty payload bit. It verifies that the three
source operations implement `(h,d)->(h+d,d)`, that the inverse shear restores
the exact pair and payload, and that the child digit interchange is an
involution. It also checks the actual bit-network constants satisfy
`s_b < W_b m` and the row-divisibility condition at `k=1` symbolically, with
`R=W_b` and one child row per role. A negative control drops the source term
from `d <- d+h` and confirms the resulting map is wrong at `(h,d)=(1,1)`.

```sh
python3 research/typed-call-boundary/check_call_boundary.py
```

Recorded output:

```text
PASS: 9 rank-one coordinate pairs x 2 dirty payload values
PASS: inverse, spectator preservation, one-pivot child swap, and source row divisor
PASS: negative control rejects dropping the source term
This is a local exact check; it does not identify Issue 13's FSa carrier with a theorem child.
```

The check uses only Python's standard library. It tests the elementary
rank-one factorization used by the source theorem; it does not instantiate
all edges of the large finite network or replay the full tape program.

## Issue 13 comparison and cost relevance

The frozen Issue 13 result was inspected at commit
`26ff3802cfa1b4b6ee081703509c394fa71526a0`. Its checker was rerun and passed
for the reported local GF(2) map and pinned whole-graph frame records. That
checker explicitly does not test a typed recursive call. In its pinned
profile, `n_529=64,211,400` and `W=137,151,806` at `m=575` are aggregate
profile data; they do not enumerate semantic calls with input/output
payloads or frame state. The Section 4 theorem's `s_b` has a different and
precise meaning: it counts child calls generated by edge-matrix pivots in
the theorem's fixed bit network.

Adding types to the Section 4 proof does not itself change a cost. A paid
improvement would have to alter the exact Issue 13 moment term

```text
M_b(a) = (1 / (m W)) sum_t n_t t (m/t)^a
```

for identified children, while retaining the same input/output map and
charging conversions, copies, restoration, and frame transitions. All
unmapped profile rows and the rest of the multiplication construction remain
as charged. The present source gives no equation that replaces `n_529`, and
it does not isolate any moment term attributable to `FSa`.
No changed spectral radius, accepted exponent, conditional `kappa`, or
multiplication bound follows.

The missing bridge is narrow and falsifiable: one immutable producer/compiler
record must associate the specific `FSa` value and each charged use with a
specific theorem edge, factorization pivot, role row class, and child array
payload, and must show the frame diagram commutes after all copies and
cleanup are charged. Until such data exist, carrying `FSa` as a special
state token is only a proposal.
