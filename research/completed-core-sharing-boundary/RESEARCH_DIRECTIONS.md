# Falsifiable next direction

## One bounded go/no-go: bind real Section 4 child occurrences

No real cross-child payload candidate was found in the frozen core-sharing proofs. The next useful step is a bounded source-data extraction, not another PR #63 carrier search and not a typed recursion proposal.

Use one exact finite edge matrix from the selected bit supplier that feeds the original Section 4 interchange theorem. For each one in its fixed `Pi` factorization, record the actual call occurrence as

    (parent edge, pivot coordinates H_i,D_j, recursion depth, role row class,
     full array shape, spectator ranges, entrance Phi_M, exit Phi_M).

The source currently gives the finite edge matrices, their rational ranks, and the generic pivot-to-`Swap_(k-1)` rule. What is missing for a handoff is an occurrence-level binding to the complete input bit stream and its later consumer. Do not treat a rank histogram row or a child width as a child identifier.

A candidate may proceed only if two distinct occurrences have an exactly equal complete input payload and shape, the same address operation and frame, no intervening writes that change the input, and a named pair of consumers that can share the output. The owner of the output, return point and lifetime must be explicit. The cost ledger must include snapshot copies, conversions between row/field layouts, address/frame adapters, dirty spectator restoration, child return copies, and fixed-tape parking/cleanup. The conservative comparison is one saved `(V/W)F_(k-1)` term against every newly introduced cost. A positive result also needs a regenerated fully paid child multiplicity and a strict rational moment comparison under the same normalization.

**Go** only if the exact source-backed occurrence map proves that equality and the saved child term remains after all transfer and restoration costs. **No-go** if calls differ in input state, coordinate pair, row class, shape or frame, or if producing the second consumer's input costs another child-equivalent computation. Until that data exists, no specific shared value or child pair is nominated.

A separate outer-cover construction could change the child work matrix itself, but it is outside this first checkpoint and is not specified as a second candidate here.
